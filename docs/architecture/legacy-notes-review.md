# Legacy Notes and Obsidian Review

The Obsidian knowledge vault and canonical memory were reviewed before V1
preparation.

They primarily describe the retired ZenOps implementation: five public roles,
team mowing records, subcontractor and brushcutter portals, and several
specialized forestry workflows. Those notes remain useful historical evidence
but conflict with the new authoritative GitHub specification in several areas.

## V1 authority decision

- GitHub `/docs` and accepted ADRs define V1.
- Initial V1 roles are `ADMIN`, `LEADER` and `WORKER`.
- Approval follows the current Project Leader.
- Work records are individual WorkDays with project-specific WorkEntries.
- Legacy roles, screens, tables and workflows are not copied automatically.
- Legacy data remains preserved for a future explicitly approved migration.

No separate user-authored ZenOps proposal was found in the Obsidian `Inbox`.
If a legacy behavior is wanted in V1, it must be reconciled with the current
business rules and recorded as a new accepted decision before implementation.
